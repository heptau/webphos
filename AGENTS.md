# AGENTS.md

Information for AI agents working on Lumifex (formerly miniPaint, a web image editor, vanilla JS + HTML5 canvas, no framework).

## Commands

| Command | Purpose |
|---|---|
| `npm run server` | dev server (webpack serve) |
| `npm test` | Jest (ts-jest + jsdom), tests in `tests/*.test.ts` |
| `npm run lint` | ESLint (`src/js public tests scripts`) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run build` | production build into `dist/` + `scripts/post-build.js` (copy to `docs/` for GitHub Pages) |

`VERSION` in the root is the only source of the application version (read by webpack and by `make build`); new things go to `CHANGELOG.md` under `## [Unreleased]`. `dist/` and `coverage/` are in `.gitignore` (a release goes to `docs/` through `make build`; `npm run build` alone copies only `index.html` and the images to `docs/`).

Before finishing a change run `npm test` and `npm run lint`. `dist/` and `docs/` are **build artifacts** (`docs/` is committed, `dist/` is not; do not edit them by hand; file hashes change with every build). Do not build unless the user wants it.

## Structure

```
src/js/
  main.js, app.js          entry point, global `app` object (State, Actions, GUI, Layers…)
  config.js                global state (`config.layer`, `config.TOOL`, `config.LANG`…)
  config-menu.js           definition of the main menu (declarative)
  config-shortcuts.js      keyboard shortcuts with modifiers (Ctrl/Cmd, Shift, Alt)
  core/                    base-layers, base-state (undo), base-gui, base-selection, gui/*
  actions/                 undo/redo actions (see actions/_README.md)
  modules/<menu>/<x>.js    one class = one menu item (edit, file, image, layer, effects, tools, view, help)
  tools/                   tools in the toolbar (brush, selection, fill…)
  libs/                    pure helper libraries - testable without the DOM (adjustments.js, shortcuts.js…)
  languages/*.json         translations (key = English text)
tests/                     Jest tests (TypeScript importing JS from src/)
```

## How the menu works

An item in `config-menu.js`:

```js
{ name: 'Invert', shortcut: 'Ctrl+I', ellipsis: false, target: 'image/adjustments.invert', parameter: 'x' }
```

`target` = `<module folder>/<file>.<method>`. The module `src/js/modules/image/adjustments.js` is loaded dynamically and the method of the class (default export) is called. Modules are singletons (`if (instance) return instance;`). `ellipsis: true` adds "…" (a dialog). `parameter` is passed to the method.

## Adding a new feature (procedure)

1. **Pure logic** goes to `src/js/libs/` as exported functions over `{data, width, height}` (ImageData-like); keep the alpha channel and sanitize the inputs (`clamp`, `parseInt`).
2. **Module** in `src/js/modules/<menu>/` (or an extension of an existing one). To change the pixels of a layer use the pattern from `modules/image/adjustments.js`:
   - `Base_layers.convert_layer_to_canvas(null, true)` → modify → `app.State.do_action(new app.Actions.Update_layer_image_action(canvas))` (this guarantees undo/redo).
   - dialog with a live preview: `Dialog_class.show({title, preview: true, effects: true, params: [...], on_change, on_finish})`.
   - the layer must be `config.layer.type == 'image'`, otherwise `alertify.error(t('This layer must contain an image. Please convert it to raster to apply this tool.'))`.
3. **Menu** in `config-menu.js`; the **shortcut** belongs to the shortcut registry (see "Keyboard shortcuts" below: the text in `shortcut:` of the menu item or an entry in `config-shortcuts.js`); the module must not attach its own `keydown` handler - otherwise the user could not redefine the shortcut.
4. **Translations**: English is the development language - write all texts, comments and documentation in English; the English text is also the key of every dictionary. Add translations of new texts (menu names, parameter labels) at least to `languages/cs.json`, the reference translation (other languages fall back to English). Call the text through `t('…')` from `modules/tools/translate.js`; parameter labels of a dialog and menu items are translated automatically by their key.
5. **Tests** for the logic in `libs/` go to `tests/`.
6. Update the "Finished features" table below.

## Selection and mask

- The tool `tools/selection.js` holds a rectangle (`selection`). On top of it is `core/selection-mask-state.js` (`Selection_mask_class.get()`), which returns `{mask, kind: 'rect'|'custom', rect}` or `null` when nothing is selected. The mask is an 8-bit alpha channel the size of the canvas (`libs/selection-mask.js`, pure functions).
- A "custom" mask (invert, feather, ellipse, color range…) is bound to one rectangle (its bounds). As soon as the rectangle changes (new selection, undo, move) the mask stops being valid and the selection is a plain rectangle again - there is no need to cancel it by hand.
- Consumers of the selection take the mask through `new Edit_selection_class().get_mask()`: `apply_direct()` in `modules/image/adjustments.js` (mixes the original and the adjusted image through `blend_with_mask`), `modules/edit/fill.js`, `Selection_class.delete_selection` (`erase_with_mask`). A rectangular mask has a fast path without mixing.
- Tools that create a mask (`tools/lasso.js`, `tools/magic_wand.js`) inherit from `core/base-mask-tool.js`: they share the rectangle and the mask state with the selection tool (their own `Base_selection` settings with `data_function` pointing to `Selection_class.selection`), handle Feather and Shift/Alt (`commit_mask`) and draw the overlay. The result is stored through `Edit_selection.set_mask(mask, false)`. The `on_leave` of a tool must survive the start of the application (when a saved tool is restored, `app.Layers` does not exist yet). Tools with `keep_selection: true` in `config.TOOLS` do not delete the selection when switching between them (`actions/activate-tool.js`); the optional method `on_switch_keep_selection()` only cancels the unfinished state of the tool. A new tool = a file in `src/js/tools/`, an entry in `config.TOOLS`, an icon in `images/icons/` and a line in `src/css/layout.css`. Tool icons are a uniform set: SVG 24×24, no fill, black stroke 1.5 with round caps (the color in a theme is handled by a CSS filter), solid only for small highlights.
- Undo/redo of the mask: every change of the mask goes through an action. `Set_selection_action` and `Reset_selection_action` clear the custom mask and restore it on undo; `Set_selection_mask_action` (`actions/set-selection-mask.js`) sets a new mask for the current rectangle. An operation that changes both the rectangle and the mask therefore puts `Set_selection_action` into a `Bundle_action` and `Set_selection_mask_action` right after it (that is what `Edit_selection.set_mask` does). Do not change the mask directly through `Selection_mask.set_custom`/`reset` inside a user operation - it could not be undone.
- A dialog with a live preview of the mask: `Edit_selection.preview_dialog({title, params, compute, on_finish})` (calls `compute(params)` after a short pause, the result is drawn in orange instead of the selection through `Selection_mask.set_preview`; it is closed together with the dialog). `Dialog.show` has the option `live: true`, which calls `on_change` also while a slider is dragged, without an image preview. Make new operations with the mask through `mask_dialog` (a function `(mask, params) => new mask`).
- A new operation with the selection = a function in `libs/selection-mask.js` + `Edit_selection.set_mask(mask)` (sets the rectangle to the bounds of the mask and registers the mask).

## Keyboard shortcuts

- There is one source of truth, the registry (`libs/shortcut-registry.js`, pure functions, no DOM), and its manager `core/shortcut-manager.js` (a singleton that holds the defaults and the user's changes in `localStorage` `lumifex_shortcuts`; only deviations from the defaults are saved; they are validated on reading). A shortcut is a text ("spec") `Mod+Alt+Shift+Key`; `Mod` = Ctrl, on macOS Cmd (as before). The registry consists of (1) menu items with `shortcut:` and `target`, (2) `config-shortcuts.js` (the default `shortcutsDefinition` and the named exports `EXTRA_SHORTCUTS` - tools, colors, New/Close document, groups…, `REPLACED_MENU_SHORTCUTS` - texts in the menu that are no longer the default (bare letters belong to tools), `FIXED_COMMANDS` - commands that are shown but cannot be changed: Cut/Copy/Paste are handled by the browser and Delete by the tool that has something to delete). The command id is the `target` or `target|JSON(parameter)`, tools have `tool:<name>`. The test `quick-wins.test.ts` checks that the default shortcuts have no conflict, that bare letters are used only by tools and colors (`X`, `D`), Q (Quick Mask) and `[` `]`, and that the basics (Ctrl+Z/Y/Shift+Z, O, S, Shift+S, A, D, T, +/−, Alt+Ctrl+I) exist.
- The key is recognized by `event_key`: a letter by `event.key` (on QWERTZ the Z key is still Z), digits and letters of other alphabets by the physical key (the Czech number row, Option+letter on a Mac), punctuation by the physical key; Shift is ignored for `+` and `−`.
- `Base_gui` listens to `keydown` with a single listener: `Shortcuts.find(event)` → an entry with `tool` (`GUI_tools.activate_tool`, holding the key does not switch again) or with `target` (`run_target`); it is ignored while typing into a field and while a dialog is open. Modules therefore have no key handling of their own for commands (only contextual keys are left: Esc, Enter, Delete, Backspace in tools, space = hand, arrows, Ctrl+X/C for the clipboard).
- The texts of shortcuts in the menu and in the context menu (`gui-context-menu.js`) are taken from the manager (`apply_to_menu` overwrites `shortcut` in `menuDefinition`, `text_for`), so they follow the user's changes.
- Editor: Lumifex > Keyboard Shortcuts… (Alt+Shift+Ctrl+K) and the last tab of Settings (`modules/tools/shortcuts_editor.js`): search, groups, click a shortcut and press the new keys (Backspace removes it, Esc cancels), a conflict is reported with the name of the command and the change is not accepted, commands require a modifier or an F key (bare letters only for tools and colors), ↺ restores the default, "Reset all" everything. Inspired by OmniDB (`go-server/frontend/src/shortcuts.js`).
- Export and import (buttons in the editor): the file `lumifex-shortcuts.json` = `{format: 'lumifex-shortcuts', version: 1, shortcuts: {id: spec}}` with deviations from the defaults only (`export_shortcuts`); the import (`import_shortcuts`) does not trust the file - it checks the size (200 kB), the shape and the version, takes only known commands with a valid shortcut that are not fixed, a conflict (a shortcut that another command already has) means skipping; imported changes replace the current ones (what the file does not mention goes back to the default).
- A key is processed once per press: when held, `keydown` repeats (`event.repeat`), and a command that toggles something (rulers, grid, panels) would switch back and forth; only commands with `repeat` may repeat (brush size, zoom, undo/redo - `REPEATABLE` in `shortcut-manager.js`). Shortcuts are not blocked when a checkbox, slider or button has the focus (after a click on them the shortcuts used to stop working), only when the user is typing (`is_typing_target` in `libs/shortcuts.js`: text, number, textarea, select, contenteditable).
- Shortcuts that the browser takes (`BROWSER_RESERVED` in `libs/shortcut-registry.js`: Cmd/Ctrl+T, N, W, Q, R, L, M, `,`, H and their Shift variants) are not always captured by the page - they work in the installed application, not in a browser tab. The editor shows ⚠ for them and warns on assignment. That is why the rulers do not have Cmd+R (in Safari it reloads the page, the state is lost) but Alt+Ctrl+R; Free Transform, Transform Again, Levels, Curves, New and Settings have the standard Photoshop shortcuts and ⚠.
- The default tool shortcuts are as in Photoshop: V, M, L, W, Shift+W, C, I, Shift+I, J, Shift+J, S, Y, B, Shift+B, E, Shift+E, G, K, R, Shift+R, O, Shift+O, T, U, P, H, Z. The former bare letters of commands (S/O save/open, I information, R resize, L rotate, T crop, F auto, D duplicate, G grid, N/U) are gone; in their place Ctrl+S, Ctrl+O, Shift+Ctrl+S, Alt+Ctrl+I (size), Alt+Shift+Ctrl+I (information). Ctrl+N, Ctrl+W and Ctrl+T are taken by the browser, so New document = Alt+Ctrl+N and Close document = Alt+Ctrl+W.

## Effects and layer styles

- Styles that draw themselves (Stroke, Inner Shadow, Color Overlay) inherit from `effects/abstract/layer-style.js`: it handles the dialog with its own preview (`draw_preview`), the cache (`cached(layer, key, build)`) and the transformation into the layer space (`transform_to_layer`); a style that needs more images per layer uses different `slot`s in `cached()`. Stroke draws the outer part in `render_pre` (under the image) and the inner part in `render_post`, the other styles in `render_post` (over the image; in `render_post` set `ctx.filter = 'none'` and restore it, so that a shadow from another filter is not applied to the overlay). A file name with a hyphen (`inner-shadow.js`) = the filter name = a method with an underscore (`inner_shadow`) - otherwise editing the filter in the layers panel does not work.
- Live layer filters are modules in `src/js/modules/effects/**` (`render_pre(ctx, filter, layer)` is called before the layer is drawn, `render_post` after it, `demo()` draws the preview in the Effects browser). The list of filters of a layer is `layer.filters` (`Add_layer_filter_action`).
- The CSS `ctx.filter` is cheap only for a single blur (`drop-shadow` with blur, Glow). **Chaining many `drop-shadow` filters is unusable performance-wise** (3 s for 16 filters on 800×600), so Stroke draws its own outline into a cache (`WeakMap` by layer, key = image + size + color).
- Values from filters can come from a saved project - do not put anything into CSS strings without validation (`safe_color` in `libs/layer-styles.js`).

## Layer mask

- `layer.mask` = `{width, height, values[], counts[]}` (RLE, 255 = visible), `layer.mask_enabled === false` turns it off. It lives in the coordinates of the layer, so it moves, resizes and rotates with the layer. It is changed only through `Update_layer_action` (undo/redo works), never directly.
- `Base_layers.render_object` draws a masked layer onto a temporary canvas, clips it with the mask (`destination-in`) and composes it; `render_object_plain` draws without the mask. Effects and styles of the layer are therefore masked together with it. Pixel edits (`convert_layer_to_canvas(id, true)`) do not see the mask and work with full pixels.

## Look (macOS + Photoshop)

- The look follows Apple HIG: color tokens (`--accent`, `--separator`, `--field-background`…) are in `css/reset.css` for `:root` (dark), `body.theme-light` and `body.theme-green`; the structure and components are overridden by `css/macos.css` (loaded after the other CSS). Add a new color as a token to all three themes, not hard-coded.
- Name and icon: the application is called Lumifex; the icon (a brush, a glass prism, a rainbow) is a single source image `images/lumifex-source.webp`, from which `scripts/make-icons.sh` (ImageMagick) creates `manifest/192x192.png` (also the favicon and the logo in About), `manifest/512x512.png` and the social preview `lumifex-preview.jpg` (from `lumifex-preview.webp`, referenced by `og:image` in `index.html`). Rounded corners are made by a mask. The maskable icons (`manifest/*-maskable.png`) are supplied by hand, the script does not touch them; the manifest does not need more sizes; `apple-touch-icon` in `index.html` points to the opaque `manifest/192x192-maskable.png`.
- The transparent menu blurs the content below it: the blur (`--vibrancy`) is on `.main_menu::before` (a layer behind the bar), not on `.main_menu` - an element with `backdrop-filter` is a "backdrop root" and the expanded menus inside it (all of them are descendants of `.main_menu`) would then blur only the bar.
- Touch devices (iPad) have no right button: holding a finger (500 ms, no movement over 10 px, one finger only; `libs/long-press.js`, `attach_long_press`) opens the same context menu on a layer row and on the canvas; on the canvas only with tools that do not paint on touch (`CONTEXT_MENU_TOOLS`: Move, Hand, Zoom, selections, Crop, Eyedropper, Measure, Text) - with brushes a touch is the start of a stroke. The end of the touch after the hold is cancelled (`preventDefault`), so no click is produced; the menu is also closed by a touch outside.
- Menu: on macOS shortcuts are shown as ⇧⌘D (`format_shortcut_mac` in `libs/shortcuts.js`). Dialogs (`libs/popup.js`): the title in the middle, a red close circle on the left, buttons on the right (Cancel, the default OK in blue), the class `has_preview` for dialogs with a preview.
- Main menu: the first item is the name of the application in bold (`app_menu: true` in `config-menu.js`; About, Settings), then File, Edit, Image, Layer, Select, Effects, View, Tools, Help (the order as in Photoshop for Mac). The language of the application is chosen in Settings. The menu opens already on mouse down, the item is run only on mouse up over it (`on_mouse_down_menu` / `on_mouse_up_menu` in `gui-menu.js`); three dots in names are "…" without a space. Items inside menus are ordered as in Photoshop (the Type menu after Layer: Character, Paragraph, Style, Case, Warp Text, Rasterize Type, Paste Lorem Ipsum; File: New, Open, Open Recent | Save As… | Export ▸ | Print; Edit: Undo/Redo, Cut/Copy/Paste, Find, Fill/Stroke, Transform, Define; Image: Adjustments (Brightness/Levels/Curves…, Vibrance/Hue/…, Invert/Posterize…), size, rotation, information; Layer: New, Style, Fill/Adjustment, Mask, Group, Arrange, Merge/Flatten; Select: All…, Color Range, Modify, Transform, Save/Load; View: Proof, Zoom, Rulers, Guides, Snap; Help: Search). Effects is divided into categories like Filter in Photoshop (Blur, Distort, Noise, Pixelate, Render, Sharpen, Stylize, Other; on top the Effect browser, Common Filters and Instagram Filters; a new effect belongs to a category, not to the first level). Content Fill is in Edit, Search in Help, and the Tools menu keeps only the custom tools.
- The toolbar on the left has two columns in groups as in Photoshop; the order is determined by `get_ordered_tools()` in `core/gui/gui-tools.js` (independent of the order in `config.TOOLS`); groups have an even number of tools (they are read row by row in two columns) so that no gap is left before a separator - add a new tool so that this stays true. Both the left and the right panel start right below the menu. The order as in Photoshop: Move, Marquee, Lasso, Quick Selection, Magic Wand | Crop, Eyedropper, Ruler, Healing, Patch, Red Eye, Brush, Pencil, Clone Stamp, History Brush, Eraser…, Gradient, Bucket, Blur, Sharpen, Smudge, Dodge, Sponge… | Pen, Type, Shape, Hand | Zoom.
- Texts of options in a dialog (`values` of a `select`) are translated through `t()`; add a new text to `languages/cs.json` (key = English text).
- Dialogs with fields (a parameter table or a preview; not alerts, tabs or special windows with `className`) have the class `side_buttons` (added by `popup.js`) and, as in Photoshop, the buttons in a column on the right: OK, Cancel and below them Preview (CSS grid, `display: grid !important`, because `popup.js` sets an inline `flex`); the dialog with the curve (`.curve_editor`) is wider. Alerts and confirmations have the buttons in a row at the bottom.
- Dialogs with a preview (`has_preview`): the preview on the left, parameters on the right, a Preview checkbox, dragging the preview shows the original, Alt changes Cancel to Reset (`reset_params`), next to a slider there is a number field and dragging the label changes the value.
- The Layers panel is in the right column at the top below Colors and fills the rest of the height; its header holds the blend mode and the opacity of the active layer (`sync_layer_props`). Layer details are collapsed by default.
- The rulers have ticks that follow the mouse (`ruler_marker_x/y` in `middle_area`, `View_ruler.update_markers`: mouse position − corner of the work area − 20 px = coordinate on the ruler canvas, the same as `begin_x/begin_y` in `render_ruler`; they are DOM elements with `transform`, so the rulers are not redrawn; they are hidden when the view is rotated and when the rulers are off).
- Colors: foreground `config.COLOR`, background `config.COLOR_BG` (X = swap, Edit > Fill with Background Color, Ctrl+Backspace). Rulers (Ctrl+R) and guides are created by dragging from a ruler; Ctrl+; hides the guides, Shift+Ctrl+; toggles snapping.
- Fit (the Fit button, Ctrl+0): `fit_zoom_percent` (`libs/zoom-fit.js`) returns the nearest smaller whole percent, never larger, and leaves 2 px at the edge of the canvas; the image therefore always fits into the free space.
- Navigation: the mouse wheel scrolls, Ctrl/Cmd/Alt + wheel (or pinch) zooms, Space + drag = hand, the zoom percentage is editable in the status bar.
- The Window menu (`libs/panels.js`) hides/shows panels (the state is in the cookie `panel_*`, Tab hides everything); File > Open Recent keeps the last 8 files in IndexedDB (`libs/recent-files.js`); the right button on the canvas and on a layer opens a context menu (`core/gui/gui-context-menu.js`).
- Export: offers only the formats that the browser can do (`libs/export-formats.js`); BMP is encoded by our own `libs/bmp.js`. The accent color follows the system (`AccentColor`), the green theme has its own.
- Tests guard the translations (`tests/translations.test.ts`: menu, dialog titles, the `empty.json` template) and the contrast of the themes (`tests/theme-contrast.test.ts`).
- Closing the only document (the cross on a tab, Alt+Ctrl+W, Delete on a tab) replaces it with an empty new document of the same size (the program always has a document; with unsaved changes it asks first).
- Document tabs (`core/gui/gui-documents.js`): the active document lives in the application, the others are saved as project JSON (`export_as_json`) and loaded back on switching; the history (undo) belongs to the active document, so it is cleared on switching. File > New (and the "+" in the tabs) opens a new document in a new tab (`before_new`). The History panel is in the right column (`core/gui/gui-history.js`, the event `minipaint:history` from `base-state`).
- Dialogs: the preview keeps the aspect ratio of the image (`fit_preview_size`), `{heading: '…'}` in the parameters inserts a section heading, the dialog is `aria-modal`, holds the focus (Tab) and returns it after closing. Resize links width, height and percent (Keep proportions), New file fills the size from a preset and the orientation.
- Accessibility: the menu can be operated with the keyboard even after opening it with the mouse, the toolbar has arrows (roving tabindex), the active layer has `aria-current`, the status bar is not `aria-live`; `prefers-reduced-motion` and `prefers-contrast: more` are respected.
- Translations: the other languages contain only real translations (none empty or identical to the key); add a new text to `cs.json`, run `npm run translations:sync` (it completes `empty.json`) and translate it to the other languages too (the test `translations.test.ts` checks for empty values).
- Resolution (dpi) belongs to the document: `config.RESOLUTION` (`null` = the default from Settings, `Tools_settings.get_setting('resolution')` returns the value of the document, `get_default_resolution()` the default); it is changed in Image > Information, saved in the project JSON (`info.resolution`) and a new document starts with the default.
- The size units belong to the document just like dpi (`config.UNITS`, `libs/units.js`: pixels, inches, cm, mm, points, picas; `get_setting('default_units')` returns the unit of the document). New file, Canvas Size and Resize have the fields Width/Height + Units + Resolution (dpi) linked through `libs/dialog-units.js` (changing the unit converts the numbers, changing the dpi keeps the physical size, below it is "Pixels"). Resize has "Resample": without it the pixels are not changed and the dpi / the other dimension is recalculated (like Image Size in Photoshop).
- Image information (size, mouse, resolution) is in the status bar at the bottom (`#status_bar`, `core/gui/gui-information.js`), not in the right panel.
- The empty first layer (`type == null`) has no pixels and the tools that work on pixels (`RASTER_TOOLS`) refuse it, so when such a tool is chosen the layer turns itself into a transparent image of the document size (`needs_raster_layer` in `libs/raster-tools.js`, `GUI_tools.activate_tool` and `update_disabled_tools` → `Layer_raster.raster_empty`; when a tool is chosen, the conversion and the tool choice are a single history step (`empty_actions` + `Activate_tool_action` in one `Bundle_action`), so one Undo restores both the empty layer and the previous tool; the only empty layer of a document is replaced automatically when an image is pasted, an empty layer between others has to be deleted); the "Rasterize" button in the layers panel is enabled also for the empty layer. At startup `config.layer` does not exist yet, so the code around `render_layers` must expect `null`.
- Moving and resizing the selection: the rectangular selection (the Marquee tool) has handles (`Base_selection` with `enable_controls`, the finished size is set by `finish_resize` as one history step; a soft or shaped selection is stretched with the rectangle through `fit_mask_to_rect` = `transform_mask`) and dragging inside moves only the outline. The Move tool has the option "Selection content" (`Content` default / `Outline` / `Layer`): a press inside the selection drags the pixels of the selection (Alt = copy, the rest of the layer gets a transparent hole), only the outline, or the whole layer as before; it is drawn live through `layer.link_canvas`, the change is made after the mouse is released as one step (`modules/edit/selection_move.js`, pure functions `lift_pixels` / `put_shifted` / `point_in_selection` / `moved_rect` in `libs/selection-move.js`), Esc cancels; the content works only with an unrotated, unstretched, unlocked image layer, and pixels that move out of the layer are lost. On a vector layer (stroke, text, shape, opened SVG) the layer is drawn into pixels of the image size when pixels are dragged and the result is a new image layer in the place of the original (the original layer is deleted, Alt = copy: the vector stays and a new layer "… copy" with only the selected part is created), all in one history step; during the drag the vector layer is hidden and the result is drawn through `config.view_overlay`. The Marquee tool (rectangle, ellipse) works on any layer because it only draws a shape (it is not in `RASTER_TOOLS`); the lasso, the wand and others that read pixels stay for images only. The Move tool therefore does not delete the selection when switching from the selection tools (`keep_selection`), draws it as marching ants and cancels it when leaving for a tool without a selection (`on_leave`). `Set_selection_action` and `Reset_selection_action` always work with the settings of the `selection` tool (`find_settings('selection')`), not with the active tool - with the Move tool the "selection" would otherwise be the layer and Undo would overwrite its `link`.
- Auto-select of the Move tool (`auto_select_object` in `tools/select.js`, `pick_layer` in `libs/auto-select.js`): on press the topmost layer with a visible pixel under the pointer is selected, but the active layer counts as hit everywhere in the frame where the pointer shows the move arrows - a thin stroke has many transparent places in its frame and a press there must not select the image below it.
- Resizing a layer by handles (`core/base-selection.js`, `libs/resize-ratio.js`): Shift, Option (Alt) and Ctrl/Cmd all toggle the aspect ratio - an image keeps it by default and the key releases it, a vector layer (stroke, shape, text) is free by default and the key keeps the ratio (only for corners; for edges one axis is dragged).
- Strokes of the brush and the pencil are stretched when a layer is resized by the handles: after each stroke the size of the strokes is stored in `width_original` / `height_original` and `stroke_scale` (`libs/stroke-scale.js`) turns the ratio `width / width_original` into the scale with which `render` draws the strokes (live and after the mouse is released); for older layers without `width_original` and for the stroke being drawn the scale is 1. A stretched layer is no longer used for the next stroke (`is_stretched`), a new layer is created so that the new stroke is not stretched with the others.
- Tools that can work only with a raster layer (`libs/raster-tools.js`, `RASTER_TOOLS`) are disabled (grey) in the left panel while a vector layer (text, shapes) is active; `GUI_tools.update_disabled_tools()` is called from `render_layers`. Add a new tool that reports "This layer must contain an image" to the list. The same applies to menu items: `libs/menu-availability.js` (`is_menu_item_disabled`, by `target`) greys them out in the menu, `gui-menu.js` reads it when the menu is opened; a new item that requires an image layer belongs to the lists there.

## Conventions

- The style of the surrounding code: tabs, `const`/`let` (no `var`), template strings and arrow functions instead of `var _this = this` (ESLint guards this, `npm run lint` must report nothing), no framework, no new dependencies without a reason. The file format (tabs, LF, a newline at the end of the file) is set by `.editorconfig`, the exceptions are described in it. An import used only for its side effect (a jQuery plugin, a polyfill) is written without a name (`import './x.js';`), otherwise lint marks it as unused.
- No sending of data to a server (privacy-first); external calls only through the existing `url-validator`/`input-validator` libraries.
- Validate user input from URLs/files (`libs/input-validator.js`, `libs/url-validator.js`).
- Settings (theme, language) are saved to cookies through `libs/cookie-config.js`; the theme/language have an `auto` mode (by the system, `libs/system-preferences.js`), which is the default; `?lang=` in the URL overrides the language.
- English is the development language: code, comments, documentation and commit messages are in English; communicate with the user in the language they use; commit messages following Conventional Commits (`feat(scope): …`, `fix: …`, `docs:`, `ci:`, `chore:`; see `CONTRIBUTING.md`).
- Do not add personal data of customers (PII) to code, tests or answers.

## Notes and limitations

- Saved selections are not part of the project JSON (they are in the IndexedDB of the browser, shared by all documents); transfer between computers is through Select > Import / Export.
- The page has a Content-Security-Policy without `blob:` in `img-src`: decode images from files through `createImageBitmap(file)` or `FileReader` (a data URL), not through `URL.createObjectURL` + `Image`.
- The preview in the dialogs of image adjustments (`show_dialog`) shows the whole layer, even if the result is applied to the selection only.
- The application knows only one active layer, so aligning several layers to each other at once is not possible (Distribute takes all visible ones).
- English is the source language (the keys of the dictionaries); the reference translation is Czech (`cs.json`); `empty.json` is a template with all keys for translators.

## Performance

Measured in a browser on a 4000×3000 document (12 Mpx) with ten layers through `convert_layers_to_canvas` (median; GPU canvas times are rough, always measure with `getImageData(0,0,1,1)` at the end): ordinary layers ≈ 0.4 s (≈ 40 ms per layer), an adjustment layer adds 0.1-0.4 s depending on the adjustment (Hue/Saturation is the most expensive, the others are LUTs or simple loops), Blend If ≈ 0.15-0.2 s per layer. `Base_layers.render_objects` draws everything up to the topmost adjustment / Blend If layer once onto a running backdrop of the document size (`needs_backdrop`, the parameter `inline_backdrop`), so the cost grows linearly (3 adjustments + Blend If: 1.6 s, before 9.3 s; the output is bit-for-bit the same). Layers above the topmost such layer are drawn directly (sharp even when zoomed). Live rendering (`render_objects_cached`, called by the main canvas and the Navigator) keeps the layers below the active layer in a cache (`get_backdrop_cache`: one canvas of the document size, the validity is guarded by `stack_signature` from `libs/layer-signature.js` - the signature includes all visible properties of a layer, the identity of the image / mask / points and the size of the document, so it need not be invalidated by hand anywhere; the back canvas is deliberately `willReadFrequently` so that the colors come out the same as without the cache). When zoomed above 100 % the cache is used only if all layers below the active one look the same drawn once and enlarged as drawn directly (`is_pixel_exact`: an adjustment, or an unrotated, unstretched, unblurred image on whole pixels - from 100 % it is enlarged by the nearest pixel; vector layers are drawn sharper than the raster of the document, so they rule it out). The cache is not used with clipping masks when a group extends past the boundary of the active layer, with fewer than two layers below the active one, and above 100 Mpx. Adjustment / Blend If layers above the active one are computed over the cache and the result is kept for the second call (the Navigator). While the mouse button is held (dragging a layer, a slider in an adjustment dialog; `track_pointer` / `interactive_scale`), adjustment and Blend If above the active layer are computed on a reduced copy of the document (`preview_scale`: a budget of 2 Mpx per frame, a document up to 3 Mpx is not reduced; the work goes through a transformation of the canvas, `render_adjustment` / `render_blend_if` with `current` take the size from the canvas), and after the button is released it is immediately redrawn in full size; the reduced preview costs 0.1 s instead of 0.7 s per frame and differs by 0.3 levels on average. Measured on 12 Mpx, 10 layers: nothing changes 5 ms, a stroke with the active layer without an adjustment above it 3-4 ms instead of 22 ms, with two adjustments above it 1.0 s instead of 2.6 s per frame (the backdrop is recomputed, the remaining cost is the math of the adjustments); the output is bit-for-bit the same as without the cache. Micro-optimizations of loops (e.g. preallocating arrays in `hueSaturation`) brought nothing - V8 handles them itself.
